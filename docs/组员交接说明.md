## 3. 正确分工

### 你：成果整合与 Git 负责人

你已经完成本轮主要计算与审查，后续负责把关而不是包办两位队友的工作。

1. 维护 `main` 分支、正式结果表和阶段总结的一致性。
2. 给 coding 与 modeling 两条工作线提供当前基线、验收数值和结论边界。
3. 审查 Pull Request：确认代码能复现、模型没有换口径、结果没有无依据升级为“全局最优”。
4. 冻结最终版本并组织三人交叉审稿。

验收标准：仓库可克隆；关键脚本可导入；三份 Excel 与 README/总结中的数值一致；每次正式数值变化都有提交记录和解释。

安泰队友不是只负责“把结果写成人话”，而是正式接手代码工程与复现。

1. 克隆仓库并建立独立环境，先通过 `compileall`、Q1 基线和 Q2-Q5 的 `--help` 检查。
2. 依次复现 Q1/Q2，再复核 Q3-Q5 保存的 JSON 和三份 Excel；不得一开始就覆盖正式文件。
3. 给 Q2-Q5 统一命令行参数、随机种子、输出目录、运行时间和逐次多起点日志；尤其补齐 Q5 九次多起点的逐次记录。
4. 生成 Q3-Q5 时间轴图、联合新增区间图和 Q5 的 `J_sum-J_min/J_all` 权衡图。

6. 如需重构，优先做不改变数学含义的模块化；每次重构前后必须跑数值回归。

建议分支：`coding/repro-baseline`、`coding/q5-logs`、`coding/figures`。  
验收标准：提供运行命令、环境版本、随机种子、耗时、输出文件和基线差异；差异超出当前认证区间时必须暂停合并并说明原因。

数院队友负责把现有计算提升为评委可审查的数学模型，而不是另起一套与代码不一致的模型。

1. 独立审查完整圆柱遮蔽判据，补齐阴影集合凸性、上下边缘圆周充分性以及有限线段条件的证明。

3. 复核 Q2 连续段上界、Q3 核心分支 7.9 s 上界、Q4 主分支 11.839 s 上界，逐条注明假设、必要条件和适用域。
4. 将 Q5 的 `J_sum`、`J_min`、`J_all` 写成统一集合语言，并说明主目标选择与 Pareto 权衡。
5. 将每问整理为“假设—变量—模型—算法接口—验证—结论边界”，为最终论文提供可直接使用的模型段落和伪代码。
6. 主动标出尚未证明的性质，例如单球有效时间集合连通性和 Q3-Q5 完整域全局最优性。

建议分支：`modeling/occlusion-proof`、`modeling/objectives-bounds`、`modeling/paper-formulation`。  
验收标准：每个“充要、上界、最优、近优”均有明确证据；公式中的量纲、变量域和代码参数可以一一对应。

## 4. 两条工作线如何对接

| 交接项 | coding 负责人提供 | 建模负责人检查 | 合并条件 |
|---|---|---|---|
| 观测算法 | 输入、输出、误差控制、回归结果 | 是否严格对应有限线段与完整圆柱定义 | B/C 或独立复核无矛盾 |
| 优化结果 | 参数、随机种子、耗时、多起点日志 | 目标与约束是否写对，结论是否越界 | 数值在认证或解释范围内 |
| 上界证书 | 参数盒、保护量、终止记录 | 必要条件、分支域和假设是否完整 | 不能把分支界写成全局界 |
| 图表与 Excel | 坐标、时间区间、舍入回代 | 表头、单位、目标口径 | 与正文和 JSON 一致 |
| Q5 多目标 | Pareto 候选和权衡图 | 三目标定义与选择理由 | 不跨口径直接比大小 |

## 6. Git 协作规则

1. 不直接向 `main` 强推；每个任务使用独立分支和 Pull Request。
2. 不提交 `__pycache__`、虚拟环境、临时渲染、编辑器目录和大体积无关文件。
3. 保存正式数值的 JSON/XLSX 不允许无说明覆盖；新结果先写新文件并在 PR 中比较。
4. 代码改变数学含义时，必须同步更新模型文档；模型改变参数或目标时，必须通知 coding 负责人更新测试。
5. 合并前至少由另一位成员复核；最终版本由你统一冻结。
